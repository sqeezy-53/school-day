# Сборки и выпуск School Day

Основное дерево sqeezy-53/school-day задаёт версию в Cargo.toml. Один подтверждённый тег vX.Y.Z и его полный SHA передаются всем платформам. Windows продолжает собираться workflow основного проекта. Android и Flatpak собираются в отдельных репозиториях sqeezy-53/school-day-android и sqeezy-53/school-day-flatpak. Тег проверяют на соответствие Cargo.toml. Исходный SHA включён в метаданные каждого пакета.

Для теста вручную запустите build.yml в каждом репозитории с полным SHA или существующим тегом. Тестовые файлы остаются в Actions. Для общего запуска доступен локально подготовленный prepare-distribution.yml. После его согласованного применения настройте секрет DISTRIBUTION_DISPATCH_TOKEN. Ему нужен доступ Actions write только к двум репозиториям сборок. Подойдёт токен GitHub App или fine-grained token. Обычного GITHUB_TOKEN для запуска соседних репозиториев недостаточно.

## Подпись и публикация

- Android использует постоянный ключ в защищённом окружении android-signing либо локальную подпись. CI сохраняет unsigned APK, проверяет собранный пакет и после подписи сравнивает SHA-256 сертификата. Режим draft создаёт черновик после успешной подписи. Опубликуйте его после отдельной приемки. Debug APK имеет отладочную подпись.
- Flatpak готовит bundle, исходники, контрольные суммы и OSTree. Сопровождающий подписывает OSTree постоянным GPG-ключом в копии предыдущего дерева. Статический HTTPS-хостинг обслуживает само дерево OSTree и инструкции установки. Одиночный bundle служит для ручной установки. Сборочные репозитории остаются приватными до отдельного решения о распространении.
- Перед публикацией подтвердите SHA Windows, Android и Flatpak, сохраните контрольные суммы, проверьте обновление с предыдущей версии и подписи. Архивы исходников прикладываются вместе с пакетами.

Тег v0.6.2 сохранён для воспроизведения старых выпусков. Для 1.0.0 сначала проверьте Windows на выбранной ветке и Android и Flatpak по полному SHA. Android в режиме candidate готовит неподписанный Release APK для проверки. После подтверждения постоянных ключей, подписанного канала Flatpak и обязательных проверок создайте официальный тег. Публикация каждого черновика выполняется владельцем. [Ключи и резервные копии](signing.md).
