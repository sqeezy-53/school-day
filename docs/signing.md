# Ключи выпуска School Day

Подготовку выполняет владелец на своей машине. Храните пароль Android и пароль GPG в менеджере паролей. Отдельная резервная копия ключей нужна для выпуска обновлений при потере компьютера. Рабочее дерево Git для ключей не используется.

## Android

Откройте собственный терминал. Команда сама запросит пароль и сведения сертификата.

```sh
umask 077
keydir="$HOME/.local/share/school-day-signing"
mkdir -p "$keydir"
chmod 700 "$keydir"
test ! -e "$keydir/android.p12" &&
  keytool -genkeypair -storetype PKCS12 -keystore "$keydir/android.p12" \
    -alias school-day -keyalg RSA -keysize 3072 -validity 10000
keytool -list -v -keystore "$keydir/android.p12" -alias school-day
```

Сохраните зашифрованный android.p12 на отдельный защищённый носитель. Для контрольной проверки сравните SHA-256 обеих копий. Проверьте, что резервный контейнер открывается и содержит тот же сертификат. У PKCS12 пароль ключа совпадает с паролем контейнера.

В репозитории school-day-android используйте окружение android-signing с ограничением на основную ветку и ручным подтверждением. Загрузите ключ прямо из файла, через pipe в уже авторизованный gh. Ввод пароля оставьте защищённой форме GitHub, отдельно для ANDROID_STORE_PASSWORD и ANDROID_KEY_PASSWORD. В переменных окружения задайте ANDROID_KEY_ALIAS со значением school-day и ANDROID_CERT_SHA256 с SHA-256 отпечатком сертификата.

```sh
base64 -w0 "$keydir/android.p12" |
  gh secret set ANDROID_KEYSTORE_BASE64 -R sqeezy-53/school-day-android --env android-signing
```

Фоновые тестовые задачи получают только общедоступные исходники. Режим подписи проверяет APK и отпечаток после сборки. Режим draft готовит черновик. Если ключ хранится только офлайн, подпишите локально через ci/sign.sh согласно документации Android-репозитория.

Если ранее был установлен Debug APK, сначала экспортируйте данные и проверьте копию. APK с другим сертификатом Android не установит поверх текущего. После принятия решения об установке официальной сборки сохранённые данные можно импортировать и снова сопрячь устройства.

## Flatpak

Используйте отдельное хранилище GPG. Задайте пароль при создании ключа.

```sh
umask 077
keydir="$HOME/.local/share/school-day-signing"
mkdir -p "$keydir/flatpak-gnupg"
chmod 700 "$keydir" "$keydir/flatpak-gnupg"
gpg --homedir "$keydir/flatpak-gnupg" --list-secret-keys --fingerprint
```

Если список пуст, выполните gpg с тем же --homedir и параметром --quick-generate-key 'School Day Flatpak' ed25519 sign 0. Если ключ уже создан, продолжайте использовать его.

Скопируйте закрытый каталог GPG вместе с сертификатом отзыва на отдельный зашифрованный носитель. Проверьте копию через отдельный --homedir, сверив отпечаток. Закрытый ключ остаётся офлайн. Скрипт ci/stage-signed.sh в Flatpak-репозитории подписывает копию дерева OSTree локально. Публикация получает только подписанные данные и открытый сертификат. После подписания проверьте установку и обновление через сохранённый открытый ключ в отдельном профиле.

Для будущей выдачи приложению нового обновления используйте тот же сертификат GPG. Менять публичный ключ существующего remote можно только с подготовленным переходом доверия.
